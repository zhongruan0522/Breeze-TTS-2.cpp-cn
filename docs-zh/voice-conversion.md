# 声音转换

声音转换用另一个声音重述一段已有录音。词语及其时间点来自源录音，声音来自参考音频。不需要源录音的转录文本。

这是与克隆不同的操作。克隆用克隆来的声音朗读你提供的文本。声音转换则是对你已有的音频改变说话人，同时保持原有表达的时间节奏。

## 工作原理

编解码器分为两个阶段，它们一起训练但分开存储：一个语义码本承载正在说的内容，十五个声学码本承载它的音色。

转换对源音频编码，强制骨干网络逐帧输出源的语义码，并让深度解码器在参考声音条件下重新生成全部十五个声学码本。内容得以保留是因为它是复制来的，音色发生变化是因为它是重新生成的。

骨干网络仍需要文本可读。提示为空时它会退化，在该状态下强制码会输出含糊不清的结果，因此会自动生成一段长度与片段相当的填充文本。填充文本说了什么并不重要，只要数量大致相当于片段的长度即可。在一个 14 词句子上测得：

| 提供的文本 | 完整保留的词数 |
| --- | --- |
| 完全没有 | 7 / 14 |
| `Hello.` | 10 / 14 |
| 长度合适的通用填充文本 | 13 / 14 |
| 刻意错误的文本，长度合适 | 13 / 14 |
| 正确的转录文本 | 14 / 14 |
| 自动填充文本 | 14 / 14 |

错误文本与通用填充文本得分相同，这是有用的结论：词语来自强制码，而不是来自提示。在困难素材上，用 `--text` 提供真实转录文本仍有轻微帮助。

## 命令行

```
breeze-convert <model.gguf> --source <in.wav> --ref-audio <voice.wav> --ref-text <s> --output <out.wav>
```

| 参数 | 默认值 | 含义 |
| --- | --- | --- |
| `--source <wav>` | 必填 | 要转换的录音。任意采样率或声道数。 |
| `--output <wav>` | `convert.wav` | 输出路径。 |
| `--ref-audio <wav>` | 必填 | 目标声音。 |
| `--ref-text <s>` | 必填 | 参考音频的精确转录文本。 |
| `--text <s>` | filler | 源录音的转录文本（如果你有）。 |
| `--temp <f>` | `0.3` | 深度采样温度。 |
| `--top-k <n>` | `1` | 深度 top-k。 |
| `--keep-acoustic <n>` | `0` | 从源音频保留而非重新生成的声学码本数量。 |
| `--cfg-scale <f>` | `1.0` | 向目标声音引导的强度。 |
| `--seed <n>` | `42` | 随机数种子。 |
| `--cpu` | off | 强制使用 CPU 后端。 |

还有两个参数用于深入查看编解码器的行为，而非日常使用。`--feed-source` 把原始帧而非转换后的帧送回骨干网络，这会让源声音泄漏回来。`--keep <n>` 只用前 `n` 个码本重建音频，完全不改变声音。

## `POST /v1/audio/convert`

通过 HTTP 的同一操作。接受 `multipart/form-data`。

| 字段 | 类型 | 默认值 | 含义 |
| --- | --- | --- | --- |
| `source` | file | 必填 | 要转换的录音。 |
| `ref_audio` | file | 无 `voice_id` 时必填 | 目标声音 WAV。 |
| `ref_text` | string | 无 `voice_id` 时必填 | 参考音频的精确转录文本。 |
| `voice_id` | string | 无 | 使用已保存或缓存的声音，代替上传音频。 |
| `text` | string | filler | 源录音的转录文本（如果已知）。 |
| `temperature` | float | `0.3` | 深度采样温度。 |
| `top_k` | int | `1` | 深度 top-k。 |
| `cfg_scale` | float | `1.0` | 向目标声音引导的强度。 |
| `keep_acoustic` | int | `0` | 从源音频保留的声学码本数量。 |
| `seed` | int | `42` | 随机数种子。 |

与 `/v1/audio/speech` 不同，它在一个响应中返回整段音频而不是流式输出，因为转换需要先把整个源编码完毕才能开始。响应头相同：`X-Sample-Rate` 和 `X-Sample-Format`，正文为原始 s16le PCM。

```
curl -X POST http://127.0.0.1:8137/v1/audio/convert \
  -F "source=@recording.wav" \
  --form-string "voice_id=harbour" \
  -o converted.pcm
```

注意这种不对称：HTTP 端点接受已保存的 `voice_id`，而 `breeze-convert` 只接受通过 `--ref-audio` 提供的片段。从命令行转换总是要重新编码参考音频。

## 采样范围被刻意收窄

默认设置接近贪心，这对这个模型来说并不寻常。放开采样会让源声音重新渗入，因为说话人身份位于采样所随机化的声学残差中。

以转换输出与各说话人的相似度衡量，把男声源转换为女声目标：

| 设置 | 与目标相似度 | 与源相似度 | 区分度 |
| --- | --- | --- | --- |
| `temp 0.3, top_k 1` | 0.9760 | 0.7648 | **0.2112** |
| `temp 0.3, top_k 10` | 0.9840 | 0.7978 | 0.1862 |
| `temp 0.6, top_k 20` | 0.9815 | 0.7852 | 0.1963 |
| `temp 0.9, top_k 50` | 0.9761 | 0.8263 | 0.1498 |

随着采样放开，泄漏稳步上升。默认设置的区分度最干净。如果困难素材掉词，`--temp 0.6 --top-k 20` 是比完全放开到模型正常设置更温和的折中。

## 旋律效果时好时坏

音高与其他内容一同重新生成，因此目标声音提供自己的语调，而不是照搬源的语调。对歌唱源，结果会以目标的自然音域重新演唱，而不是原来的音高。

曲调是否真正保留因片段而异，所以请实际测试你的素材，不要依赖经验法则。两个源与其原曲的对比测量：

一段 12.7 s 的歌唱片段，不借助任何手段时曲调丢失：

| 路径 | 中位 F0 | 轮廓相关系数 |
| --- | --- | --- |
| 源音频经编解码器编解码往返 | 275.9 Hz | +0.901 |
| 转换后，`keep_acoustic 0` | 258.1 Hz | -0.200 |
| 转换后，`keep_acoustic 1` | 266.7 Hz | +0.580 |
| 转换后，`keep_acoustic 2` | 272.7 Hz | +0.725 |

一段 5.3 s 的流行人声，两种方式下都明显是演唱：

| 路径 | 中位 F0 | 轮廓相关系数 |
| --- | --- | --- |
| 源音频 | 229.7 Hz | |
| 转换后，`keep_acoustic 0` | 187.5 Hz | +0.065 |
| 转换后，`keep_acoustic 1` | 269.7 Hz | -0.208 |

注意第二种情况：两个版本听上去都无疑是演唱，但相关系数接近零或为负。这是移调造成的。该版本以不同的音域跟随曲调的轮廓，逐帧的音高相关会把它判为不相关。**请用耳朵判断这个功能。只看相关系数会误导你。**

`keep_acoustic` 直接从源音频复制指定数量的低阶声学码本，而不是重新生成。音高位于低阶码本中，因此设为 1 或 2 能让更多原始轮廓得以保留，同时声音仍以目标音色输出。

超过 2 就不稳定了，而且在普通语音上弊大于利。同样的设置用在一段口语音频上，把音高范围从 107 Hz 扩大到 320 Hz，并产生了可听见的颤音抖动。**语音请保持 0。歌唱先试 0，如果曲调变得平淡再用 1 或 2。**

提供 `--text` 在歌唱上比任何其他场景都重要。同一段片段在无文本转换时输出的内容是 "Does it pinch I? Send my tears"，而传入歌词后精确输出为 "drink it up, I have no fear"。

## 长度

长素材没问题。一段 141 s 的录音在 RTX 3060 上以 Q8_0 转换约需 137 s，接近实时，而且全程保持音高。

声码器以窗口方式解码结果，而不是一次性完成，因为对长片段建一张单一的图需要一次性分配数 GB 内存。源编码仍然一次完成，因此比这更长几倍的录音在繁忙的 GPU 上仍可能耗尽内存。

## Web UI

VOICE CHANGER 标签页提供同样的功能，`keep_acoustic` 对应 KEEP MELODY 控件。它走 HTTP 而非 WebSocket，因为转换一次性返回整段音频，没有可流式传输的内容。
